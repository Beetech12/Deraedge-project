# Deraedge on Vercel: NGN payments

The Paystack account is naira-only. Checkout uses NGN; the existing USD display
prices ($100, $200, $500) remain in the source. No exchange rate is calculated.
The three fixed naira prices must be explicitly supplied in integer kobo.

## 1. Connect persistent storage

Open the Vercel project, select **Storage**, and connect a **Neon Postgres**
database through the marketplace. Choose the appropriate plan yourself. Connect
it to the project's **Production** environment. Confirm that it provides a
`DATABASE_URL` environment variable (use the pooled connection string). Keep this
value private. Do not paste it in chat, browser code, or a tracked file.

Vercel functions cannot use the local SQLite file as durable storage. This
backend refuses a SQLite fallback on Vercel. It creates the new Postgres tables
on first connection, inside a transaction protected against concurrent cold
starts. Existing local SQLite orders are not migrated automatically; retain
their database and backups if they contain real enrollments.

## 2. Set Production environment variables

In **Settings > Environment Variables**, add these nonsecret values:

```dotenv
PUBLIC_URL=https://deraedge-project.vercel.app
ALLOW_LIVE_PAYMENTS=true
PAYMENT_CURRENCIES=NGN
PAYSTACK_CONFIRMED_CURRENCIES=NGN
TERMS_URL=https://deraedge-project.vercel.app/deraedge-enroll/terms.html
PRIVACY_URL=https://deraedge-project.vercel.app/deraedge-enroll/privacy.html
REFUND_URL=https://deraedge-project.vercel.app/deraedge-enroll/refund.html
POLICY_VERSION=2026-09-28.1
```

Privately add `PAYSTACK_SECRET_KEY` from the live Paystack dashboard and the
database-provided `DATABASE_URL`. Copy the **existing approved values** for
`PRICE_FOUNDATION_NGN`, `PRICE_PROFESSIONAL_NGN`, and `PRICE_MASTERY_NGN` from your
local configuration. They are kobo, not naira: the value must be 100 times the
price in naira. Do not reuse test fixtures as real business prices.

Do not upload `.env` or prefix private credentials with `PUBLIC_`/`NEXT_PUBLIC_`.
Local `.env` edits do not change Vercel environment variables. Leave USD out of
the two currency lists unless Paystack explicitly enables it on your account.

The URLs above are the deployment targets for the included policy pages. Review
their contents before publishing. They returned 404 on the old deployment;
the new function checks for successful HTML responses and blocks live checkout
until they are actually published. Preview deployments always block live keys;
use test keys and a separate test database for previews.

## 3. Deploy the updated project

Deploy the repository including `api/index.js`, `server/`, `scripts/`,
`vercel.json`, the frontend/policy pages, `package.json`, and `pnpm-lock.yaml`.
The project uses Node **24.x** and the **Other** framework preset. The checked-in
configuration sets the build command to `node scripts/build-static.cjs` and
the output directory to `public`. Remove conflicting dashboard overrides if
they exist. The generated public directory excludes private server files,
environment files, tests and databases. The API runs as a Vercel function;
do not use `node server/start.cjs` as a Vercel build command.

Environment changes require a redeployment. Confirm these pages return 200:

- `/deraedge-enroll/terms.html`
- `/deraedge-enroll/privacy.html`
- `/deraedge-enroll/refund.html`
- `/api/catalog` (JSON with `currencies: ["NGN"]`)

The catalog returns `enabled: false` and safe explanations if storage,
policies or payment configuration are incomplete. A failing database connection
cannot silently switch to temporary storage. Policy availability is cached for
up to a minute; retry after publishing.

## 4. Configure Paystack and verify the deployment

Set the live Paystack webhook URL to:

```text
https://deraedge-project.vercel.app/api/paystack/webhook
```

Make that endpoint reachable by Paystack without Vercel deployment protection
or an interactive login. Never disable webhook signature checks. The callback
URL is generated by the backend for each enrollment. Initialization and
verification use the private server key; browser redirects cannot mark orders
paid. Amount, currency, customer, reference and test/live mode must match.

Use `npm run deployment:check` to check public routes without creating a charge.
Then perform an authorized end-to-end payment and verify the receipt and stored
order. Automated tests use a simulated provider, not real money. A successful
authentication check alone does not prove a completed live payment.

## Local validation

```powershell
pnpm install --frozen-lockfile
npm test
npm run build
npm run deployment:check
```

For the browser suites, install Playwright or use the bundled runtime already
available in this workspace:

```powershell
$env:NODE_PATH='C:\Users\BEE TECH\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\node_modules'
npm run test:payments:browser
npm run test:messages:browser
```

To develop locally, use a **test** key and `PUBLIC_URL=http://localhost:3000`.
Leave `DATABASE_URL` unset to use the local SQLite database. Do not replace your
live `.env` with the example. Keep real keys out of test fixtures and commands.

## Email and operations

Contact/partnership forms use the same durable database. Supply the existing
SMTP variables privately on Vercel if email is needed. In a function, delivery
is awaited rather than left in an untracked background timer; pending retries
are processed by subsequent message submissions/status requests. Without
further requests they remain queued. A scheduled worker would be needed for
unattended retries. An interrupted send is marked unknown after its lease
expires and is not blindly resent. Configure database backups and retain the
existing local database separately.

The operator command `node server/orders.cjs list` uses `DATABASE_URL` when set.
Run it only in a trusted terminal; it displays order data. Vercel has no public
admin or database-inspection route.
